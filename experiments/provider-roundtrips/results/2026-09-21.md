## Interpretation

The comparison clears the bar for productionization of the combined-status successful readback path. Persistent Node transport also earns a follow-up production design, but the current synchronous observation interface prevents simply swapping `curl` for async `fetch` without widening the change.

The smallest production-safe next step is therefore:

1. add a certified combined-status observer;
2. use it for positive GitHub commit-status settlement;
3. preserve the existing paginated status-list observer for absence/indeterminate semantics;
4. separately make provider observation asynchronous before replacing all `curl` reads with persistent `fetch`.

This result does not authorize treating one combined-status page as authoritative absence.
